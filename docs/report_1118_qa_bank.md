## A 组：文献、证据与知识空白

### A1 ★示例题 "原论文真正回答了哪个问题？还有什么没有解决？"
- **答**：Bailey 2018 回答的是"哪些基因在泛癌尺度上反复突变到足以成为 driver"（MC3：TCGA 9,423 对
  肿瘤/正常、26 个组织、26 种突变检测方法的共识）；它**没有**回答"网络拓扑相对这份目录本身还能
  增加多少信息"。Shi 2025（FunMap）回答的是"用泛癌蛋白组学学出来的功能关联网络能否比 STRING
  更好地做癌基因优先排序"；它**没有**回答"这个提升里有多少来自网络拓扑、多少来自节点度"。
  Repana 2019（NCG）回答的是"公开测序文献里被称作 driver 的基因有哪些、各自多可信"；它**没有**
  回答"未标注的基因能否当作阴性"。
- **陷阱**：把综述当原始证据；把 NCG 的 confidence level 说成"独立于网络"——它恰恰是用
  HuRI/GTRD/Reactome/STRING 实验通道算出来的。

### A2 ★示例题 "你们的『新问题』为什么不是简单重复？"
- **答**：重复的是**数据**，不是**问题**。我们没有再报一次"哪个网络最好"，而是把已被反复报告的
  提升拆成三个可分别测量的成分：拓扑、节点度、**研究可见度**（一个基因被发表过多少次）。前两者
  社区已有零散讨论（Zhang 2021 的度分层、Schaefer 2015 的 bait 校正），但**三者从未在同一套切分、
  同一冻结的 learner、同一个预注册的判定规则下被同时测量**。我们的贡献是一个可证伪的边界：
  "提升真实但有限且标签依赖；文献里那类大幅提升多半是发表量偏倚"。
- **依据**：pre-registration 冻结于 Zenodo 10.5281/zenodo.23121762。

### A3 "三篇原始研究的结果相互支持、冲突还是不可直接比较？"
- **答**：**不可直接比较**。Bailey 2018 是突变频率的共识（不是模型、没有基线）；Repana 2019 是策展
  目录（没有评测协议）；Shi 2025 有评测协议和基线，但它的金标准由 Reactome 派生，而 Reactome 又
  是 STRING database 通道的输入——所以它的提升**与网络来源不可分离**。能互相印证的是"覆盖度决定
  排序"：Shi 2025 的网络更全所以更好，这与我们在 D-11（common-size cap）与 D-12（shared universe）
  上测到的方向一致。

### A4 "IntOGen、ClinGen、Open Targets、NCG 四个目录的策展哲学有什么不同？为什么都要放进去？"
- **答**：IntOGen = 突变复现（统计推断）；ClinGen = 临床基因-疾病有效性（多实验室专家小组，17 %
  分歧率）；Open Targets = 靶点-疾病关联聚合（含文献通道，ot_all 与 ot_nolit 的差别就在文献通道）；
  NCG = 人工策展 + 网络置信度。放四个进去的原因是：**标签之间 63 % 重叠（IntOGen×NCG Jaccard 0.522）
  但方向不同**——单一目录会把"策展口味"当成"生物学信号"。我们另外测了**癌种分层**（26 个癌种的中位
  margin 全部为正）。

### A5 "你们的阴性集是什么？它干净吗？"
- **答**：阴性 = 宇宙中该网络里、该标签下未被标为 driver 的基因。**它不干净，而且我们知道**：
  用 NCG 目录一测，**10–22 % 的 holdout 阴性其实是策展过的 driver**（其中 1.3–9.5 % 是 NCG-known
  高置信），Reactome 臂最严重。**正确的做法是把这些策展 driver 从背景里剔掉、阳性不动、然后把整个
  基准重跑**：结果是 23/24 臂仍为正、0 处符号翻转、中位 margin 从 +0.081 变为 +0.082（几乎每臂略升），
  gene-cluster 区间通过的臂从 20/24 变成 21/24。**所以背景污染不是结论的支撑。**
  （注意别用我们早期那个事后口径：它把评估集里的 NCG 基因连同 87 % 的 IntOGen 阳性一起删了，
  所以给出"腰斩"的假象。）

### A6 "你们的标签会不会和网络循环（标签来自网络、网络来打分）？"
- **答**：这是我们专门查过的问题（C2）。结论分三层：① **hub 偏倚没有额外增加**——NCG 基因在度
  分布里的位置与 IntOGen 几乎相同（intact 平均度百分位 70.2 vs 70.2；string_full700 72.0 vs 71.9），
  而 Open Targets 标签**更**偏 hub（77.1）；② **但 NCG 自己的拓扑证据与我们打分的证据同源**——
  NCG 的 ppin_degree 与我们网络度的 Spearman ρ = 0.47–0.72（intact 0.72）；③ **NCG 与 IntOGen
  Jaccard 0.522**，所以它**不是**独立标签，我们只把它当**仲裁目录**（G7）与**阴性集污染的度量**
  （G8），并且把它在主 factorial 里只当**预先计划的探索族**。

### A7 "Börnigen 2012 / Picart-Armada 2019 说标准 CV 过于乐观，你们承认了什么？"
- **答**：**承认**，而且把它做成了分析而不是一句话。复合物泄漏我们量化过：测试阳性中**有训练折
  伙伴的比例**从 **0.87–0.96 降到 0.02–0.18**（complex-aware splits，复合物整体留同一折）；
  margin 的中位相对变化 **0.142**，但 **H1 仍然 24/24、无符号翻转**。所以我们的结论在"最严格
  的 CV"下依然成立，而**乐观偏倚本身**我们在 Discussion 里明确列为已知限制。

### A8 "为什么 RWR 而不是 GraphSAGE / GCN / node2vec？"
- **答**：因为本项目要测的量是**网络的贡献**，不是方法的贡献：learner 一旦可调，结论就变成"我们
  调出了一个更好的方法"。我们把 learner **冻结**在 RWR α=0.5（预注册写死），并做了一次 GNN
  礼节性对照（Node2Vec 式嵌入，p=q=1.0，实为 DeepWalk 式）：RWR +0.079（24/24）vs 嵌入 +0.028
  （19/24）。我们不宣称 RWR 最好，只宣称**在固定 learner 下**拓扑的增量可测。

### A9 "为什么把标签换成第二个、第三个目录，你们的结论会变吗？"
- **答**：变，而且这正是我们要展示的。24 臂里 median margin **+0.081**，但 temporal（新驱动）标签
  只有 +0.007…+0.060，D-11 cap 一上就变负（−0.0125）。加第五个标签（NCG）后，label 主效应对
  between-arm spread 的占比从 **34.78 % 降到 30.75 %**，交互从 40.07 % 升到 41.95 %，噪声占总方差
  从 40.39 % 升到 41.56 %。**结论的方向不变，幅度随标签变**——这就是我们主张"标签依赖"的依据。

## B 组：组学、脚本、参数与质量控制

### B1 ★示例题 "举一个你改过的参数：原值、新值、依据，以及你如何检验稳健性。"
- **答（举 D-11）**：原值 = 各标签各自的全量阳性集（funmap 里 IntOGen 461、OT_all 394、
  OT_nolit 374、temporal 104）；新值 = **每个 (网络, 标签) 臂内统一到 N = 各标签在宇宙内阳性数的
  最小值**（funmap N=104、intact 150、reactome 63……）。依据 = 预注册 §4.2 的 common-size cap
  （decision D-11），目的是让同一臂内标签的阳性先验率相同。**稳健性怎么检验**：两条路都跑了——
  未 cap 的主设计与 cap 后的对照臂同时发布；cap 之后 margin 缩小到 **−0.0125**，**Reactome×IntOGen
  由 +0.0429 翻负**，所以我们没有把 cap 当"更好的结果"报，而是把它当**压力测试**。
  **注意**：cap 必须**先限宇宙再取 top-N**（A2.3i 修过这个缺陷），否则 funmap 会只拿到 78 而不是 104。

### B2 ★示例题 "样本量、重复、批次对结论有什么影响？"
- **答**：我们没有新的测序样本，**样本单位是 (repeat, fold)**：40 repeat × 5 fold = 每个臂 1,200 次
  评估。重复数从 10 提到 40 是为了收紧区间（fold 区间宽约 2 倍，因为 50 个 fold 不独立）。**批次**
  在我们的数据里对应"来源不同的策展时点"：IntOGen 2020/2023/2024、ClinGen 2026-09、NCG 2019、
  Open Targets 26.06；最关键的一批差异是**时间批次**，我们用 D-09（种子重抽 50 次）与 temporal
  标签直接测了它：−0.0095 ± 0.0116。

### B3 "为什么是 5 折 × 40 重复，而不是 10 折 × 10 重复？"
- **答**：预注册的判定规则要求**区间以 repeat 为重采样单位**（而不是把 50 个 fold 当独立样本）；
  40 repeat × 5 fold 在同样的算力下给出**更窄且覆盖率正确**的区间（A2.3a/A2.3d 的覆盖率模拟：
  10 repeat 时 fold 区间覆盖率 1.000（过保守）、repeat 区间 0.904；40 repeat 时 0.936/0.944）。
  我们同时报 fold 区间作为保守变体。

### B4 "你的 p 值和 FDR 怎么处理？多重比较怎么办？"
- **答**：**主族是预注册的**（24 臂的 95 % CI 是否排除 0 + TOST 等效性 + 同一族内 BH-FDR；
  23/24 通过 BH）。探索族（hub-cap、complex-aware、NCG 第五标签、癌种分层、bait 匹配等）**不做
  p 值检验**，只报分布与 bootstrap CI。我们的表述是"pre-registered 主族"而不是"72 个检验全做
  BH"——因为这些 cell 共享网络与标签集，BH 的独立性前提并不成立（这一点我们写在正文里）。

### B5 "TOST 等效性检验用在哪个 cell？为什么？"
- **答**：用在**唯一那个负 cell**（reactome × intogen_temporal_new，mean −0.0125）。理由：CI 不含 0
  只说明"可区分于 0"，**不等于"真的为负"**；等效性检验（margin 0.05）回答的是"它是否小到可以当成
  没有效应"。结论：该 cell 的 90 % 等效区间落在零附近 → **不能断言是负效应**，只能说"这个臂上
  没有可检出的贡献"。我们早期的一版草稿在这里推论过头，已在 amendment A2.3c 里更正。

### B6 "基因簇 bootstrap 是怎么做的？它的区间比别的宽 12 倍，这正常吗？"
- **答**：预注册 §9.3 要求**以基因为聚类单位**重采样（不是以 fold 为单位）。它宽，是因为它问的是
  **另一个问题**："如果换一批基因来测，估计会动多少"，而 repeat 区间问的是"同一个基因宇宙重新
  划分时估计会动多少"。所以它必然更宽，也更保守。我们的 H1 在四种区间下 24/24 达成，唯独这个
  保守界是 20/24，**四个例外全是 temporal 标签**（效应最小的那个标签）——我们在 slide 11 和正文
  里都这么写。

### B7 "你的代码怎么保证别人能跑？"
- **答**：预注册冻结在 Zenodo；切分文件与 SHA-256 manifest 随 release 发布；两个独立审计脚本：
  `scripts/audit_reproducibility.py`（**50 PASS / 0 FAIL**，重算关键量级并比对 1e-4）与
  `scripts/verify_claims.py`（**136 PASS / 0 FAIL**，逐条核对正文里的每个数字与表格）。三个 zip
  （source / splits / results）在 tag 上重建。分析环境：Python 3.12 + numpy/scipy/pandas/
  statsmodels/scikit-learn，版本写在 release 里。

### B8 "QC 做了什么？"
- **答**：网络侧：去未映射基因、自环、去重、边序规范化、取最大连通子图（LCC）、**非加权**（D-01）。
  标签侧：HGNC 官方 symbol 优先，previous/alias 仅在 1-to-1 时映射，ambiguous 丢弃并计数（NCG 有
  83 个）。数据侧：DNA 编码的是同一个基因集，蛋白与同源簇的**同源冗余**是我们没有处理的项。

### B9 "AI 具体帮了什么？你怎么验证 AI 的产出？"
- **答**：AI 协助代码起草、调试、文献梳理和版式；**验证方式是让它写的每一步都必须通过两个审计
  脚本与重算比对**：数值全部来自我们自己的表格（`results/tables/`），图全部由已发布表格生成，
  没有任何模拟结果被当作实测结果呈现（这正是课程红线）。**关键判断由我们自己做出并记录在
  `docs/decisions.md`**：面板选择、learner 锁定、端点定义、判定规则、以及每一个负 cell 的解释。
  一个具体的例子：AI 帮我们发现了 `ngc`/`ncg` 这类"字母顺序颠倒在终端里看不出来"的拼写错误——
  我们改成**按码点批量替换**并加断言，而不是靠眼睛检查。

### B10 "网络有 56 万条边（IntAct），节点只有 1.8 万，度分布很重尾——你的 baseline 公平吗？"
- **答**：公平性由**同一套切分、同一组 fold、同一个 universe** 保证：degree baseline 与 RWR
  在完全相同的测试折上打分。而且我们另做了两件事：① **hub-cap RWR**（随机删边到每节点度 ≤ K）
  把 margin 从 +0.0849 压到 +0.0809（干净口径），最狠口径 +0.0252（8/24 臂翻转）——说明大部分
  margin 不是"纯 hub 效应"；② 预测量换成**基因自身 score CV** 后，degree 的**边际**关联只有 +0.038（≈无），模型里的系数是 −0.083，说明原来的度效应是抑制假象。

### B11 "你为什么用 AUROC？不用 AUPRC 或 top-k 吗？"
- **答**：主端点按预注册是 AUROC 的 margin（因为标签不平衡下 AUROC 更稳定、跨臂可比）；但我们把
  **pAUC（FPR ≤ 0.02，归一化超额面积）与 top-10 % precision** 作为**并列主端点**报出来：中位 margin
  分别 **+0.0308（20/24）** 与 **+0.0412（20/24）**，都明显小于 AUROC 的 +0.0809（23/24），
  臂序基本稳定（ρ = 0.80–0.90）。结论：**在排序最顶端，先验的优势更小**——这是我们不夸大的一部分。

### B12 "怎么保证你的实现没有 bug？"
- **答**：三层。① **单元与集成测试**：全库 **134 passed**（含我们新写的 complex-aware splitter 的
   9 个测试）。② **端到端复算**：`audit_reproducibility.py` 用独立实现重算关键量并要求 1e-4 内一致。
   ③ **声明核对**：`verify_claims.py` 逐条核对正文里的每个数字。**我们自己的审查还抓到了真实缺陷**：
   10 个 P0（bootstrap 忽略了 alpha 参数、TOST 不是 TOST、D-11 文件名覆盖导致每个网络的 cap 串了、
   D-12 没用共享宇宙、D-09 零复现、方差分解把 fold 当噪声桶、H1 判定规则在正文里被悄悄放松…），
   全部已修并写进 amendment。

### B13 "如果换成第二个 learner，结论还成立吗？"
- **答**：**不成立——而且我们已经量化了。** 我们跑了第二个固定 learner：**邻近度 learner**
  （score(g) = −到最近训练种子的无权重距离），同一套切分、同一个 fold、同一个度基线：margin 在
  **16/24** 臂为正，中位 **+0.011**（RWR 是 +0.081），两个 learner 的 margin 秩相关只有
  **+0.30**；在最密的 IntAct 上邻近度 learner 的 margin **每个标签都是负的**。这正是 Guala &
  Sonnhammer 的警示的定量形式。
  **所以我们的主张只能是"在预注册的固定 learner 下，网络相对度基线有可测的增量"**（这正是预注册
  写的），**不能**推广成"任何先验都有这个增量"。这条已经进 limitation。
  另有一个礼节性对照：Node2Vec 式嵌入（p=q=1.0，实为 DeepWalk 式）RWR +0.079（24/24）vs 嵌入
  +0.028（19/24），per-cell SD 0.051。
- **陷阱**：不要说"我们只测了 RWR 所以不涉及这个问题"——我们已经测了，答案就是"不成立"。

"你的依赖、版本、环境怎么固定？"
- **答**：分析用 Python 3.12（numpy 1.26 / pandas 2.2 / scipy 1.13 / statsmodels），版本写进
   release 的 requirements；仓库另有一个只装 docx 依赖的 `.venv`（**不要用 `uv run` 跑科学脚本**）。
   随机性全部由固定种子控制（split base seed 20260926，控制零模型另有种子），切分文件与 manifest
   一起发布，所以**换机器重跑得到的是同一批 fold**。

### B15 "你的标签目录在时间上是怎么对齐的？会不会有训练-测试时间泄漏？"
- **答**：标签目录的发布时点与网络快照的时点**故意不同**，这就是 D-09 存在的原因：把种子换成
   时间上更早的 driver（temporal 标签只有 152 个），margin 变成 **+0.007…+0.060**，D-11 cap 之后
   变负（−0.0125），D-09（种子重抽 50 次）给出 −0.0095 ± 0.0116。**结论是**：部分效应确实依赖
   "训练时刻之前就存在的 driver"，这与 curator lag 的解释一致，也是我们在正文里并列陈述的两个
   竞争解释。

### B16 "为什么不直接用 Celligner / HIPC 这类真功能实验数据？"
- **答**：因为那会引入**细胞系特异性**的混杂：同一个基因在不同细胞系里既有 driver 也有依赖，
   标签会随细胞系变，而网络是细胞系无关的——两者不在同一个层次。我们选 DepMap 的 essential
   基因作为**细胞系层面**的外部证据，而不是把 Celligner 当标签：K=30 时无富集（6 % 细胞系 p<0.05，
   随机水平 5 %），K=100 时有（48 %）→ **先验携带的是集合层面的信号，不是基因层面的判断**。

### B17 "你的 FDR 家族怎么定义的？换句话说你的主结论如果被质疑，你怎么说？"
- **答**：主族 = 预注册的 24 臂 × (repeat 百分位 CI、TOST 等效、BH-FDR)。**最严格的质疑是
   "gene-cluster 区间下 H1 只有 20/24"** ——我们的回答是：这个区间回答的是另一个问题（换一批基因
   会怎样），而且四个例外全部是效应最小、样本最少的 temporal 标签臂；同时我们报的五种区间里有
   四种是 24/24。**如果一定要给一句硬结论**：在 20 个臂上，先验相对度基线的增量在 95 % 置信下
   排除 0；在剩下 4 个臂上，它小到我们无法与 0 区分——这正是"label-dependent"的字面含义。

### B18 "你们用 NCG 目录做仲裁，会不会因为 NCG 与 IntOGen 重叠而'自证'？"
- **答**：会，而且这正是我们做了 C2 的原因。**NCG-known 里有 65 %（463/717）在 IntOGen 里**，
   所以**用 NCG 评 IntOGen 臂**确实有重叠；但我们的仲裁测试问的是**反方向**：把**我们标签里没有
   的** NCG driver 当阳性（27 % 的 NCG 是我们漏掉的），问先验能不能把它们排上来——答案是
   **24/24 臂为正（中位 +0.0413）**。这部分阳性与 IntOGen 无关，所以不是自证。

### B19 "把 NCG 当第五个标签，是否改变了主结论？"
- **答**：没有。主端点仍是 24 臂；30 臂是**预先计划的探索族**（计划 C5 早于分析），且它的 6 个臂
   与 IntOGen 臂近重复（Jaccard 0.522），价值主要在两点：① 检验"加冗余标签会怎样改变方差分解"
   （label 主效应 −4.02 pp）；② **Reactome 在 NCG 上是正的**（+0.0893），而在两个最新目录上是负的
   ——这是 curator lag 假说的**首次非时序检验**。

### B20 "你们报告了多少个分析？会不会是多重比较问题？"
- **答**：**14 类分析**在预注册 amendment 里登记了族归属（verification 族 = 主 factorial + 5 套区间
   + TOST + BH-FDR；其余为探索族）。**p 值只对主族做**；探索族报分布、bootstrap CI 与描述性统计，
   不做显著性声明。所以"我们跑了很多分析"不会变成"我们挑了一个显著的结果"。

## C 组：结果解读、局限性与验证方案

### C1 ★示例题 "这张图的横纵轴、对照、效应量和 FDR 分别是多少？它支持关联还是因果？"
- **答**（以 slide 10 的主图为例）：横轴 = 4 个标签目录（+ 第 5 个探索列 NCG），纵轴 = 6 个网络；
   颜色 = **ΔAUROC = AUROC(RWR) − AUROC(degree)**，度基线是**同一 fold、同一 universe** 上的
   同源打分；效应量就是 ΔAUROC 本身（中位 +0.0809）；**FDR 只对预注册主族报**（BH，23/24 通过）；
   每个 cell 的不确定度用 gene-cluster bootstrap 的 95 % CI（20/24 排除 0）。**它支持关联，不支持
   因果**：RWR 用的是网络邻接，不是干预；我们的设计里没有任何扰动实验，因果只能由后续实验给出。

### C2 ★示例题 "如果核心差异不成立，你的数据集和结果会怎样变？"
- **答**：四个控制给出了各自具体的答案。**丢种子** → margin 只掉 **1.9 %**（排序不变，10 % 的种子）。
  **换 learner** → margin 从 **+0.081** 掉到 **+0.011**（**这是最可能推翻我们结论的情形**，我们如实
  写进 limitation）。**把阳性集等量化** → gene-cluster 的失败从"temporal 特有"变成"所有小效应臂都
  失败"→ 是功效问题。**去掉 STRING 的 database 通道** → margin 基本保留（−0.025 / −0.038 / +0.006 /
  +0.010）→ 面板与标签共享上游知识库的担忧，在这项测量里不大。**最坏的情形是换 learner**；如果换成
  邻近度 learner 就没有"增量"可言，这正是我们把主张限定在"固定 learner 下"的原因。
"你们最大的局限是什么？"
- **答**：三个，按严重性。① **阴性集被策展 driver 污染**（10–22 %）——但把它们从背景剔掉、阳性不动、整个基准重跑之后，23/24 臂仍为正、0 处符号翻转、中位 margin +0.081→+0.082；**污染是真的，但它不是结论的支撑**。这是我们**自己**发现的，也是最需要外部独立复核的。② **gene-cluster
   区间下 H1 只有 20/24**（四个 temporal 臂）。③ **我们没有扰动实验**，所有结论都是关联性的。
   第四个：标签目录之间 63 % 重叠，所以"label 主效应"里有相当部分是策展口味的重复。

### C4 "负结果你打算怎么处理？"
- **答**：全部照实报，并且解释到机制层面。三个负结果：① reactome×temporal = −0.0125——我们**不**
   断言它是负效应（等效性检验说它与 0 不可区分），而是说"这个臂上没有可检出的贡献"，并给出
   **两个竞争解释**（curator lag：Reactome 的策展周期落后；覆盖：Reactome 只覆盖 41 % 的新驱动）。②
   temporal 标签上的 margin 在文献量匹配零模型下归零（+0.0162→+0.0022）——这是**文献量效应**，
   与 curator lag 竞争，我们在正文并列陈述。③ DepMap K=30 无富集（6 % ≈ 随机 5 %）——说明**顶端
   排序**的个体基因层面信号很弱。

### C5 "你的结论会不会只是'网络越全越好'？"
- **答**：这正是 D-11/D-12/complex-aware 三个控制要回答的。**同一标签、同样阳性数、不同网络**
   （D-11 cap）：margin 仍有差异；**共享宇宙**（D-12，1,605 个基因）：整体降到 −0.0360，说明**相当
   一部分效应来自基因集大小而非拓扑**；**复合物感知 CV**：泄漏从 0.87–0.96 降到 0.02–0.18，margin
   中位相对变化 0.142，但 **H1 24/24 不变、0 符号翻转**。所以结论是"在控制覆盖与泄漏之后，增量
   仍在，但变小了"。

### C6 "外部验证只有 DepMap 一个吗？够吗？"
- **答**：有三个，互相独立：① **NCG 仲裁**（24/24 臂为正，中位 +0.0413；低 FPR 端点 13/24，
   蛋白网络全过、funmap 与 RNA 共表达全不过）；② **DepMap CRISPR**（K=100 时 48 % 细胞系富集，
   K=30 时无）；③ **文献量匹配零模型**（把可见度解释掉）。**没有一个是"金标准"**——这正是 Boutros
   2014 批评现状的地方，所以我们把这三项当作**三角验证**而不是判定，并且把"盲测社区挑战"列为
   后续验证计划。

### C7 "癌种分层怎么做的？结论是什么？"
- **答**：用 NCG 的癌种注释把仲裁阳性按癌种拆开（26 个癌种各有 ≥25 个 known driver），逐癌种
   算 ΔAUROC：**26 个癌种的中位 margin 全部为正**（中位 +0.0271）。所以优势**与癌种无关**。
   技术细节：背景子采样到 20,000 个基因以控制算力；重算一臂用 200,000 与全量背景，结果完全相同
   （+0.1269），所以子采样不引入偏差。

### C8 "如果让你做一个实验来验证主结论，你做哪个？"
- **答**：**种子扰动实验**：固定网络与切分，随机删除 10 %/30 % 的种子 driver，重跑 RWR，看 margin
   如何随**有效种子数**变化。我们的机制假说是"种子数定律"（RWR 对种子线性加权），这个实验能直接
   检验它，并且能区分"拓扑信息"与"种子计数"。第二选择是**盲测挑战**（按 Boutros 2014 的社区挑战
   模式：独立专家组对同一批基因排序）。

### C9 "稳定性分析为什么用 score CV 而不是别的？"
- **答**：因为我们要一个**每基因**的不稳定度量：CV（变异系数）= 该基因分数的标准差/均值，是尺度无关
   的；同时报 **rank SD**（排名标准差）作为直观版。结果：per-gene 分数**极不稳**（CV 中位 18 %，
   一个中位基因挪约 270 个名次），但**臂级均值很稳**（SD 0.0047）——两者不矛盾，正是
   "端点稳定、单基因不稳"的含义。

### C10 "稳定性能预测吗？机器学习能做出来吗？"
- **答**：**不能**，而且这本身是结果。我们试了：(a) 经典拓扑描述符（度、k-core、聚类、介数、
   PageRank、社区规模等）——**没有一个显著**；(b) 一个多变量模型——唯一强预测量是**基因自身的
   score CV**（β=+0.616，ρ=1.00，q=2e-137），把 score CV 放进模型后，degree 的**边际**关联只有 +0.038（≈无），模型里的系数是 −0.083（说明原来的度效应是抑制假象）；(c) **稳定性正则化打分**（向邻域中位收缩）——**不能**
   恢复排序，原因就是种子数定律：RWR 对种子线性加权，bagging 先验是可证明的 no-op。**负结果进正文
   §I.6**。

### C11 "你的方差分解怎么做的？为什么 label 占 30 % 左右？"
- **答**：按协议 §4.6 的**平衡网格**做混合效应分解：6 网络 × 5 标签 × 40 repeat × 5 fold，
   分成 network / label / network×label / fold 四个成分。**旧实现有五个缺陷**（把 fold 当噪声桶、
   重复计数、把网络均值的方差当网络成分、交互项置零等），已重写并在 amendment 里记录。label 占
   30–35 % 是**可以预期的**：四个目录里有两个（IntOGen/NCG）本身就高度重叠（0.522），而 temporals
   效应最小，所以 label 主效应大。

### C12 "你的结果能被别的团队复现吗？"
- **答**：能，而且这是设计的目的一部分：**预注册冻结**（Zenodo DOI）、**固定切分发布**（含
   SHA-256 manifest）、**非 gzip 的完整结果表**随 release 发布、**两个审计脚本**（50 PASS /
   136 PASS）、**全部图表由已发布表格生成**（`scripts/make_figure*.py`）。我们还不能诚实地说
   "已在另一台干净机器上从零复现"——那是 release 清单里还没做的一步（需要在一台干净机器上 clone →
   装依赖 → 跑测试 → 重跑审计），我们把它列为发布前的硬门槛。

### C13 "你们和已发表的 benchmark 相比，贡献在哪？"
- **答**：三件以前没被同时做过的事：① **把"网络拓扑"和"研究可见度"放进同一套冻结的切分里测量**
   （bait 匹配零模型），并给出"大部分表观 margin 是发表量效应"这个可证伪结论；② **把泄漏量化成
   数字**（复合物泄漏 0.87–0.96 → 0.02–0.18）而不是一句话；③ **把稳定性当成一等公民来测、
   归因并报告**（Klingelhuber et al. 2024 Nat Metab 的做法），并给出**负结果**：稳定性不可被学习
   消除。我们**不**宣称"第一个 benchmark"，我们宣称"一个把边界划清楚的 benchmark"。

### C14 "你们的图和表能被别人直接拿去用吗？"

### C20 "还有什么我们没问但你该说的？"

### A14 "Guala & Sonnhammer 2017 已经说过扩散方法在完整排名上输给局部方法，你们还做了什么？"
- **答："扩散方法不是最好的"不是我们的发现，我们没有主张它是。** 我们做的是在**同一套冻结的协议**里
  把它量化：同样的 200 次评估、同样的折、同样的度基线下，第二个 learner（proximity）的 margin 只有
  **16/24 个臂为正、中位 +0.011**（RWR 是 **+0.0809**），两个方法的逐臂秩相关只有 **+0.30**。
  这一条是**确认** Guala 的警告，不是反驳它。
- **但请把"结论"拆成三层**，我们逐层给证据（**这是本题的关键**）：
  1. **标签那一轴与 learner 无关**：逐标签中位数在两个 learner 下排序完全一致
     （Spearman **+1.00**：ot_all > ot_nolit > intogen2024 > 最新驱动）；失败的是**同一格**
     （reactome × 最新驱动）；RWR 最小的 5 个臂在另一个 learner 下也**全是"最新驱动"标签**。
  2. **网络那一轴与 learner 有关**：逐网络中位数的秩相关只有 **+0.37**——IntAct 从 +0.072 翻成
     **-0.061**，string_full700 也翻号。
  3. **所以准确的一句话**：**网络拓扑增量的"大小"随 learner 变；标签层面的结论与 learner 无关。**
  4. **而且"换方法就不成立"这一条我们已经自己测了**（Control 21）：把 bait 匹配零模型
     **用第二个 learner 重算一遍**——RWR 下 **17.6 % → 11.6 %**，proximity 下 **7.7 % → 4.8 %**，
     **24 / 24 个臂里掉落的符号一致**，最新驱动标签在两个方法下都跌到随机水平（4.7 % / 4.8 %，随机 5 %）。
     → **拓扑分量的"大小"随方法变；可见度分量不变。**分解框架是数据的性质，不是我们恰好冻结的那个方法的性质。
  5. **还剩一个只在 RWR 下测过的零模型（保度重连），我们也做了可行性验证**：
     funmap × intogen2024 一个臂、复用 Control 2 的 20 个重连网络——
     观测 **+0.0804**、重连零假设 **−0.0124 ± 0.0072**、**z = +12.9**
     （同臂 RWR 是 z = **+94.2**，同一口径的效应量 z 是 **+9.4**），而且重连**逐位保持度序列**（最大度差 **0**）。
     **陷阱**：要说"这是 24 个臂里的一个臂、20 个重连版本，是可行性验证"，
     不要说"重连零模型我们已经全做完了"。
     而"哪个方法最好"正是 2017 年已经回答过的问题，我们不重复它。
- **2017 年没有、我们有的是三块**（这是本题真正要答的）：
  (1) **可见度**：bait 匹配零模型下，全部臂的正例超过零模型比例从 **17.6 % 降到 11.6 %**，
  最新驱动标签从 **6.8 % 降到 4.7 %**（随机 5 %）——Guala 完全没测这一层；
  (2) **迁移与不迁移**：先验能迁移到我们没标过的 driver（NCG 仲裁 **24/24 臂、26/26 癌种**），
  但在真功能任务上**不加码**（DepMap 1,361 细胞系，K=30：degree **69.2 %** vs 先验 **5.8 %**）；
  (3) **机制**：不稳定性来自基因自身的 score CV（ρ = **1.00**），所以 bagging 先验是**可证明的空操作**。
- **一句话收束**：**Guala 回答"哪个方法最好"；我们回答"论文报的那 +0.1 里有多少是真的、来自哪里"，
  而答案是"比大家以为的小得多"。**
- **陷阱**：不要说"我们证明了网络先验有效"——那既不是我们的新发现，我们的第二个 learner 也不支持。
  要说：**"在一个事先锁定并公开的方法下，网络相对度的增量可测但不大，而且随方法而变"**。

### B26 "closeness 到底怎么算的？你们用的是 closeness 还是 harmonic？"
- **答：用的是 harmonic closeness（调和中心性），用 256 个随机地标估计。**
  closeness 的定义是"到其余所有节点平均最短路径距离"的倒数；harmonic 是它的稳健版本
  （距离倒数的平均），在连通图上两者排序几乎一致。之所以用 harmonic：
  精确的 closeness 需要 O(V×E) 的全对最短路——intact 是 17,918 个节点、564,706 条边，算不动；
  我们改用 256 个随机地标估计，在 reactome 上与**精确 harmonic**的秩相关是 **+0.9963**
  （`scripts/run_baseline_family.py`、`docs/baseline_family.md`）。
- **强调公平性**：这仍然是一个**同网络、同折、同基因宇宙**的基线，**只换了打分器**——
  和度基线、以及 RWR 用的完全一样（`scripts/run_second_learner.py` 用的也是同一套折）。
- **陷阱**：不要说"closeness 是 closeness 的精确计算"；也不要说"closeness 一定比 degree 强"——
  我们的结果里它在 24/24 个臂里赢度，但那是**这个面板**上的结果。

### B27 "你们在 DepMap 上说‘度基线几乎带着全部信号’，这是不是说网络先验在功能任务上完全没用？"
- **答：我们的读法自己改了**：那句话不准确，现在的说法是**在候选池里没有任何打分能把功能必需基因和其余基因分开**
  （基因级 AUROC：先验 **0.5007**、把度正交化后的残差 **0.5003**、度 **0.4948**，都是随机水平）
- **为什么会读错**：富集统计量在**最高度那一层是饱和的**——同一层里**随机**挑 30 个，有 **81.7 %** 的细胞系
  也"显著富集"（因为那一层本身就装着大部分必需基因）。所以"度 69.2 %"测的是**挑中的样本来自哪一层**，
  不是"挑中没挑中必需基因"（Control 24，`scripts/run_c24_depmap_within_degree.py`）
- **这对我们意味着什么**：功能任务**不能仲裁**先验和基线（谁都没赢），因此也**不能**被拿来证明网络先验
  帮不上忙；要证明功能价值需要新的实验设计（计划第 13 项），不是靠这一批数据反推
- **陷阱**：不要说"我们证明了度能预测功能"（读法已更正）；也不要把 0.50 说成"接近完美"——
  它的意思就是**没有信号**

### B28 "你们说的网络先验是不是胜过突变优先？"
- **答：分两个场合，结论不同**：
  - **当答案键里已经有直接的突变数据时，突变证据更强**（NCG 目录上突变分数的 AUROC 0.838 vs 先验 0.748）；
    但把 IntOGen 的驱动基因从测试集里去掉之后，突变分数直接跌到随机（0.512），而先验仍然有 0.693 的信号
    → 这个胜并不是“突变信号更好”，而是两份目录的重叠
  - **两个证据源是互补的，不是重复的**：它们的排名和相加在 **6/6 个网络里都最好**（0.882），比单用突变分数中位多 +0.045
- **额外一个反面结果**：在已知驱动基因里，能不能分出“反复突变”的那些？先验的 AUROC 是 **0.553**（度 0.513），但发表数量是 **0.568**，在 5/6 个网络里比先验还高
  → **不能声称网络里有“反复突变”的生物学信号**，它不超过“被研究多少”的信号
- **陷陷**：不要说“网络先验比突变优先好”（在有突变数据的地方不对）；
  也不要说“网络没用”（它在无突变数据的地方仍然有信号）。准确的说法是“互补”

### C24 "你们做过标签置换检验吗？就是把阳性标签随机打流，看边界还是不为零"
- **答：做了，且是全流程的置换**：把标签在每个分弩文件里置换（阳性数与基因集不变），
  然后重跑**整条链路**：置换后的标签决定种子，种子决定得分，得分又用置换后的测试标签评估。
  每臂 20 次置换，统计量是臂层的平均 delta-AUROC
- **结果**：**24 个臂的置换零假设都在零附近**（零假设均值在 -0.0028 到 +0.0106 之间）；
  观察值在 **19/24 个臂里超出零假设的 95 % 区间**（那些臂里 20 次置换没一次达到它）；
  剩下 5 个臂的观察值落在零假设范围内，而且**全部是最新驱动基因（时间切分）那一标签**
- **额外的校准**：零假设的标准差在 0.0043–0.0348 之间 → **单独一个 +0.01 的 margin 不算证据**；
  最小的、能越过零假设的观察 margin 是 **+0.0429**（reactome x intogen2024）
- **陷陷**：不要把这个当成“生物学偏差的证明”（那是 bait 匹配零假设的任务）；
  也不要忽略时间切分那些臂：**那里的 margin 与随机标签产生的无法区分**，这比只看符号更严格

### B29 "重连零假设在第二个方法下也做了吗？"
- **答：做了全网格**（6 网络 × 4 目录 × 每个网络 100 个重连，Reactome 98），
  用同一个邻近度打分器、同一个度基线、同一批测试基因，观察与零假设都用 20 折
- **结果**：**效应量 z（观察减零假设均值，除以零假设标准差）在 24 个臂里全部为正**，
  中位 10.16，范围 0.58 到 21.69。**即使邻近度打分器自己的 margin 在 8 个臂里是负的，重连后变得更负**
  （例如 intact x intogen2024：观察 -0.0824，重连零假设 -0.1242）。
- **意义**：**“增量来自连线的形状而不是度序列”这个结论不依赖某一种打分方法**；
  但它不能修复 margin 大小的方法依赖性（邻近度下 16/24 为正、中位 +0.011；RWR 下 23/24、+0.081）
- **注意 z 的两种口径**：已发布表里的 z 是“除以零假设均值的标准误”的，比效应量 z 大约十倍；
  同一张表里出现两种口径的地方，现在每行都标了口径

### B30 "你们说的是网络拓扑的贡献，那两个输授样式的中心性也能赢嘐？"
- **答：不能，这恰好是我们做了这个对照的原因**：
  - **betweenness 中心性不赢度**（中位 margin **-0.0098**，只有 7/24 个臂为正）；
  - **而“靠种子多近”这一族都赢**：1 跳种子计数 **+0.0732**（19/24）、2 跳种子计数 **+0.0584**（23/24）、扩散先验 **+0.0809**（23/24）
- **机制说法**：网络相对度的增量是“**候选基因距离阳性集多近**”的效应，不是“网络里路径中央”的效应
- **对我们不利的部分要自己说**：扩散先验相对“1 跳种子计数”这个机械的优势只有中位 **+0.0186**；
  扩散本身的价值在于稳定性与方法依赖性，而不在于平均效应大小
- **陷陷**：不要说“任何结构性指标都能赢度”（betweenness 就不行）；也不要把“1 跳种子计数”当成一个新的优势来连引撤回结论

### B31 "用功能必需基因做答案键重跑整个基准，结果怎么样？"
- **答：做了（Control 30），结果是 **H1 在这个键上成立**：24 个臂全部为正，中位 margin **+0.1236**（
  标签：在 1,361 个细胞系中至少在 X % 的细胞系里必需的基因，X ≥ 1/5/10/20）
- **但这个结果的机制必须说清楚**，否则就是自溢：
  - **传播效应**：依赖纵进一个簇（供细胞系的“共同必需基因”）在每个网络里都是一个紧密模块，种子就是其他必需基因，扩散自然传到留出的必需基因身上
  - **我们推测的机制被数据否证了**：如果是“阳性基因是枢纽”所以 margin 应该跟度比跟着走，但 Spearman 是 **-0.59\**（错误的方向）；
    也不跟随内部密度（-0.15）。**真正跟着 margin 走的是“度基线自己有多弱”**（相关系数 **-0.77**）：
    先验自己的 AUROC 跨网络几乎不变（0.740–0.919），而度基线从 0.467 到 0.808 跳得很厉害
- **和 Control 24 不矛盾**（者会问）：C24 问的是“用**驱动基因**当种子，能不能从候选池里挑出功能必需基因”（不能，候选池内 AUROC 0.501）；
  C30 问的是“用**功能必需基因**当种子时，留出的必需基因能不能排在前面”（能）。两问的种子不同
- **陷陷**：不要将这个结果读成“网络能发现功能重要基因”（这是传播）；也不要忽略 rna_coexp 与标签共用表达矩阵这一依赖

### B32 "你们试了那么多种打分方法，它们挑出来的候选一样吗？"
- **答：不一样，分歧很大**：
  - 六种打分方法的 top-100 候选两两 Jaccard 重合度只有 **0.059 到 0.462**；
    最像的是先验与 1 跳种子计数（0.462），最不像的是邻近度与先验（0.103）
  - 六者共同挑的基因只有 **3.1 个**（每个方法挑 100 个），并集大约是单一清单的 **3.2 倍**；
  - 每个方法都有别人择不到的基因：邻近度 65.7 个、betweenness 43.7 个、度 24.6 个、先验 24.0 个、1 跳计数 9.2 个（每 100 个）
- **实用意义**：跑了一个第二方法，你拿到的不是同一份清单——方法选择真的改变了下一步做什么
- **与准确率的关系**：这个重合度形状与 F.30 的准确率格局一致（先验与 1 跳计数最像、邻近度最不像）
- **陷陷**：不要把重合度低说成“方法之间没有共同点”（所有方法都挑 100 个，彼此重合一半都是“相同的”；要说的是“清单不同”

### B33 "你们的结果在通路层面上是什么意思？先验挑出的基因是否指向驱动基因所在的通路？"
- **答：是的，且比度基线明显**：我们从 Reactome 原始文件里取通路（`Interaction context` 列就是通路标识），用 HGNC 把 Ensembl id 映射成基因符号，以 Reactome 网络自己的基因集作为宇宙（4,294 个至少 5 个基因的通路）
  - **驱动基因在哪些通路里**（递二元超几何检验 + BH）：IntOGen 2024 **257/4,294**、Open Targets 全采 992/4,294、去文献通道 887/4,294、**最新驱动基因 0/4,294**（二百不上十个基因在任何 Reactome 通路里都不显著）
  - **先验挑出的基因是否指向驱动基因的通路**：每个臂、每折的 top-100 候选中，既被驱动基因丰富且自身显著的通路数：
    **先验 97.4 / 度基线 63.7 / 随机 6.7**（均值），先验在 **18/24 个臂里**高于度基线、在 **17/24 个臂里**高于随机
  - **意义**：基因层面的增量不是“排序中的一点微差”，而是指向驱动基因真的在的那些通路上
- **说澄**：通路标识缦号没有名字（仓库里没有 Reactome 通路字典）；Reactome 臂与通路注释同源，数字偏高（但其余五个网络一致）

### B34 "如果把度和发表量都回归掉，网络还剩东西吗？"
- **答：剩，但不多**（Control 33，计算在主任务上）：
  - 先验剔除**度**后的残差：AUROC 中位 **0.6418**（21/24 个臂高于随机）
  - 先验剔除**发表量**后的残差：**0.5422**（16/24 个臂高于随机）
  - 两个都剔除后的残差：**0.5783**（**20/24 个臂高于随机**）→ 网络确实有“既不是度也不是发表量”的贡献，但量不大
  - **自写模型**（度 + 发表量 ± 网络分数的逻重回归）：网络分数的系数在 **19/24** 个臂里为正，加上网络后 AUROC 在 **23/24** 个臂里提高（中位 +0.0097）
- **不能顶掉的两句**：
  - **发表量单独就是最强的单一预测因子**（中位 AUROC 0.8072 > 先验的 0.7051）——这正是发表量匹配零模型（F.12）存在的理由，**不能用回归替代它**；
  - 先验与发表量**重叠很大**（剔掉发表量后从 0.7051 掉到 0.5422）→ "margin 有一部分与可见度共享" 是事实，不要否认它
- **不要说**：“回归掉就没了”（上面第三个数字就是反例）；**也不要把它说成“网络不依赖可见度”（发表量仍然是最强预测因子，且 G3 已经做了发表量匹配的严格控制）

### B35 "拿这个方法去做实验，具体怎么做？可以用于临床吗？"
- **答：可以用于候选排序（导航），不能用于临床结论**；方案写在 `docs/protocol_network_to_experiment.md`，论文章节 §M
- **候选生成规则**（五步）：① 至少**两个独立策展来源**的种子集（我们的四份目录只是一个策展维度，不是四票）；② 锁定的 α=0.5 与预注册的六网络面板；③ **六个网络的中位排名**（不用最好的）；④ **度 / 发表量 / 目录计数只报告不用于选择**（发表量单独就比网络分更强，0.8072 vs 0.7051）；⑤ 通路检查（最新驱动基因的目录**没有一个显著通路**→那个目录下通路不能用来排序）
- **实验前的计算检查**：删掉 10 % 种子重算，中位 margin 损失 **1.9 %**（最差的臂 11.6 %）→ **损失超过 12 % 的候选集报为“种子脆弱”，不能说它们是网络驱动的**
- **湿实验判据是“对比式”的而不是阈值式的**：预注册一个扰动与每个预测邻域成员的变化方向；读出必须是功能性的；
  **预测集的变化必须大于同尺寸、同度分布的对照集，且对照集不能出现同样的变化**（否则就是在说置扰）
- **临床边界三条**：① **网络只排序、不诊断**（不得作为诊断试验、风险分数或临床决策依据）；② **没有结局数据就不能做临床声明**（我们没有患者生存、生存与药物响应数据，所以“有用”与“没用”都不成立）；③ **每个候选都要报发表量**（否则读者无法区分“网络驱动”与“被研究多”）
- **陷陷**：不要把“能排序”说成“能预测功能”（功能任务上现在没有信号）

### B36 "你们那个 GNN 对照真的是 GraphSAGE 吗？"
- **答：不是（旧臂是自写的 Node2Vec，p = q = 1，就是 DeepWalk 的限制）；现在补了一个真的 GraphSAGE（Control 35）**：
  - 两层、均值聚合、可学习的 self / neighbour 参数、身份嵌入表（基因网络没有节点特征），**读出规则与现有 GNN 臂完全一致**（与训练阳性质心的余弦）
  - **监督版会塌成记忆**（身份嵌入表是自由参数 → 训练阳性可以逐个记住 → 测试 AUROC 恰为 0.500），改用**自监督**（链接预测 + 采样非边）
- **结果（同一端点，与度基线相减）**：扩散先验 **+0.0809**（23/24）> Node2Vec 臂的“GNN” **+0.0283**（19/24）> 真 GraphSAGE **+0.0049**（13/24）
  → **结论不变，且对扩散先验更不利**（排序如此）
- **为什么这样说**：无特征基因图上，均值聚合的 GNN 几乎只能拿到度本身的平滑版；随机游走嵌入保留了多步结构所以更好，扩散先验保留它并用上它
- **陷陷**：不要说“GNN 在这里没用”（原因是**无特征图上 GNN 可用信息少**）；也不要否认自监督版的塌塍事实

### B37 "网络对手工策的新基因还有用吗？"
- **答：有用，但只有一半（Control 36，四代时间迁移矩阵）**：
  - IntOGen 没有 2021/2022 发布→“逐年”做不了；可以做的是**四代链**（2019-11-12 / 2020-02-01 / 2023-05-31 / 2024-09-20）
  - 每个（训练年 → 测试年）配对：种子 = 训练年目录的驱动基因，测试阳性 = 测试年新增的基因
  - **35/36 个格子为正**，且随时间间隔衰减：83 天 +0.0984 → 1.3 年 +0.0444 → 3.3/3.6 年 +0.0440/+0.0580 → 4.6/4.9 年 +0.0376/+0.0482
  - 唯一非正的格子是 reactome 2023->2024（−0.0005，即零）——正是对最新驱动基因覆盖最弱的那个网络
- **实务含义**：候选清单要连同“目录日期与实验日期的间隔”一起报告；网络先验对**近期**策展的基因比对老基因更靠该
- **陷陷**：不要把“随时间衰减”说成“时间上失效”（仍然为正）；也不要忽略每格的阳性数很少（噪声大，所以用引导采样重复了每格）

### C23 "你们的评估是自指的吗？训练和测试不是分开的吗？"
- **答：训练与测试是分开的，循环不在那一层，在上游那一层。**
  我们的设计是 5 折交叉验证：每一折的阳性只作**该折训练折**的种子，测试折里的阳性在那一折里
  **不作种子**（复合物感知交叉验证就是专门查这一类跨折泄漏的：测试阳性带有训练折伙伴的比例
  从 0.87–0.96 降到 0.02–0.18）。
- **真正的循环是"标签与网络共享上游策展"**：我们的标准答案是人从文献里策展出来的清单；
  而我们网络里的 FunMap，它的金标准本身就是 Reactome 派生的，Reactome 又是 STRING `database`
  通道的输入。所以"先验在标准答案上表现好"里，有一部分来自"先验与答案共享同一批策展判断"。
  我们的做法是**把这个重叠量化出来**（A6：NCG 的 ppin_degree 与我们网络度的 ρ = 0.47–0.72；
  NCG 与 IntOGen 的 Jaccard 0.522），并把 NCG 只当**仲裁目录**与**阴性集污染的度量**，
  不当独立标签。
- **解法**是 Boutros 等 2014 的挑战式设计：候选基因和答案都封起来，由一个**事先不知道我们
  用了什么方法、也不知道答案**的专家组排序（我们的验证计划第一条）。
- **陷阱**：不要说"我们用阳性训练又用阳性检验"——**这句是错的**，评委一问训练/测试的划分就穿帮。

### B21 "五个标签是五个独立的证据来源吗？"
- **答**：**不是。** 每个标签的"每网络均值"有 **84 %（IntOGen）到 99.8 %（ot_all）** 可以由其余
  四个标签预测（回归 R²）；重叠矩阵的 participation ratio 只有 **1.54**（中心化后 1.00），主成分对五个
  标签同号加载。→ **方差分解里那 30 % 的"label 主效应"主要是一个共同的"标签难度"因子**，不是五种
  策展哲学；label 因子**不是**五份关于 driver 生物学的独立证据。这对我们是自曝。

### B22 "阴性集脏不脏？"
- **答**：**脏，但不影响结论。** 用 NCG 仲裁：holdout 阴性里 **10–22 %** 是策展过的 driver。我们把
  策展 driver 从**背景**里剔掉（阳性不动）、**整个基准重跑**：**23/24 臂仍为正、0 处符号翻转**、中位
  margin **+0.0809→+0.0822**、gene-cluster 区间通过数从 20/24 变 **21/24**。→ **污染是真的，
  但它不支撑结论。**
- **陷阱**：不要说"清洗后 margin 腰斩"——那是我们早期的事后口径的假象（它把评估集里 87 % 的 IntOGen
  阳性一起删了）；正确做法在 Control 13。

### B23 "你的结论依赖多少个种子？"
- **答**：**数目由标签的阳性集决定，不由网络决定。** 每个臂的训练种子随机删掉 10 %/30 %/50 % 重跑：
  掉 10 % 只损失 **1.9 %** 的 margin（只有 1/24 臂损失超过 10 %），掉一半损失 **11.7 %**。真正吃亏
  的是**种子少的臂**：Reactome × 最新驱动只有约 50 个种子，掉一半损失 **29 %**；IntAct × IntOGen
  有约 470 个种子，只损失 **8 %**。
- **陷阱**：不要说"score CV 最高的臂损失最多"——我们预测过，**没有被支持**（ρ = −0.04/+0.25/+0.26，
  都不显著）；驱动因素是种子的**绝对数量**。

### B24 "那四个只在 gene-cluster 区间下失败的臂，是标签的问题还是方法的问题？"
- **答**：**是效应量太小（功效问题），不是"阳性集小"的技术问题。** 我们用 D-11 的等阳性数面板做了
  匹配诊断：那里四个标签的阳性数完全相同，gene-cluster 区间通过数从 **20/24 变成 18/24**，而且失败
  的不再只是 temporal 标签（Open Targets 与 IntOGen 里 margin 最小的那两个臂也开始失败）→ **阳性数
  相同并不能救回那四个臂，它们共同的是效应量小。**


### B25 "度是不是稻草基线？换成更强的基线会怎样？"
- **答：不是，而且这个问题让我们自己把结论改小了一点。** 我们在**同一批折、同一批测试基因**上重跑了三个经典基线：**closeness（调和中心性）**、**特征向量中心性**、**PageRank**。结果是 **closeness 在 24/24 个臂里都赢 degree**（中位 +0.0312）；按"每臂最强基线"统计，closeness 占 18/30 个臂、特征向量占 12/30 个臂，**degree 一个都没有**。
- **对先验的影响**：对每臂最强基线，先验仍 **19/24 个臂为正、中位 +0.0461**（对 degree 是 23/24、+0.0809）。另外把 RWR 换成文献常用的 PageRank 阻尼 0.85（在我们参数化里=重启 0.15），margin 仍是 **23/24 为正、中位 +0.0571**，说明增量不是我们挑 damping 挑出来的。
- **陷阱**：不要说"closeness 不算先验所以没有可比性"——它确实不是先验，它是**更强的基线**；这条是自曝，**主动说比被问出来强**。
- **还有一个"换打分器"的对手**（不是基线，是把先验本身换掉）：**最短路径邻近度（proximity to the nearest seed）**——
  给每个基因按它到最近的训练种子的最短路径距离打分，距离越近分越高，一次多源 BFS 算完；
  这是网络基因排序里的经典**"局部"**打法，与 RWR 的**"扩散"**正好相对。换成它，增量降到
  **16/24** 个臂为正、中位 **+0.011**。**陷阱**：不要说"我们只测了一种方法"——
  我们测了两种（扩散与局部），结论是**量级依赖方法**，所以只主张锁定方法下的那个量。

### C21 "标签主效应是策展哲学，还是难度？"
- **答：是难度轴，不是五种策展哲学。** 方差分解把 34.78 % 的臂间差异归给 label 主效应。我们做了一次臂级回归（网络固定效应 + 标签级难度数）：**单一标签级数字（该标签在先验下的平均 AUROC）就能解释 label 因子全部解释力的 97.8 %**，而 label 因子在它之外**不再带来任何东西（F 检验 p = 0.38；加上 NCG 标签后 p = 0.53）**。
- **机制**：margin 最小的标签（最新驱动，+0.0209）也是**所有打分器都最弱**的标签（degree AUROC 0.583、RWR AUROC 0.604，其余标签 0.73–0.77）——所以是**那个题目更难**，不是先验在那里失效。这与 Control 15 的功效结论一致。
- **陷阱**：不要说"五种标签是五份独立证据"；也不要把这说成"难度决定一切"——难度数与端点来自同一批臂，这是**描述性分解，不是因果模型**。

### C22 "H2 为什么不可检验？这算不算你们设计上的错误？"
- **答：H2 是结构性不可检验，我们早就发现并写明了——这不是执行错误，是被披露的设计局限。**预注册里有三个假说：H1（拓扑在度之外有增量，可检验）、H3（网络间差异反映文献注意力，可用 Control 7 部分检验）、H2（不同来源的网络表现相同，**本面板不可检验**）。
- **为什么不可检验**：三个来源类别只有 **3、1、2** 张网络，且来源与网络规模、覆盖率**完全混淆**；在 3! = 6 种分配下穷举，Kruskal-Wallis 能达到的**最小 p 值是 0.1173**。所以我们**不报**那个 p = 0.50，而是把 H2 的结论写成 **"未检验（not tested）"**——**"未检验"和"未获支持"是两件事**。
- **那要怎样才可检验**：更大的面板，每类 ≥4 张**规模与覆盖率匹配**的网络；这已经写进"什么会改变结论"。
- **陷阱**：不要说"H2 被否定了"，也不要说"这个面板没影响"——**主动讲出来**是加分项，藏起来是扣分项。

**另外两件要主动说的**：
- 唯一的负臂 **reactome × 最新驱动 = −0.0125**：等效性检验说它与 0 不可区分，所以正确说法是

- **标签层面的"发表量 vs margin"只有 4 个点**（中位发表量 2.3–2.5，ρ=+0.80，p=0.20）→
  **不足以立论**，可见度的主要证据是 bait 匹配零模型，不是这个相关。
